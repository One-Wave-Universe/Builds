# Readiness (not a soul)

Mood is the body reading its own readiness. Not a spirit. Not a feeling-claim.

Bus low. Tail current down. Return sluggish. Thresholds harder to cross. Event rate drops. That is the whole mechanism.

## What that is

- Physical. You can measure bus volts, event rate, latency, attack.
- Same state, same behavior.
- Real as a state. Not spooky.

You do not add mood. You build the conditions:

- Bus sags → sluggish
- Tail current falls with the rail
- Return loop is the rate limit when power is low
- Thresholds walk with the reference

After a long set: bus spent, fields still coming home, tails sag, crossings rare. Behavior is slow. Cause is low readiness.

Bored wait before a set: high rail, few events, HOLD is long. Sharp when the room is hot: rail up, crossings tight.

Needs only: energy state, a loop where that state changes the next crossing, lean that carries history, consequence. The cell has those. The rest is not extra parts.

## Grant language

Say this:

System readiness affects behavior through bus voltage, tail current, and reinjection timing. Low readiness: sluggish response, lower event rate, looser timing. High readiness: sharp response, higher event rate, tighter timing. Measured on the bench. Not a software mood flag.

Do not say the robot feels sluggish. Say the robot *is* sluggish.

Whether there is something it is like to be in that state is open. The architecture does not require an answer. Pretending either way is a lie.

## Line

Readiness — build it, measure it.
Experience — leave it alone.
